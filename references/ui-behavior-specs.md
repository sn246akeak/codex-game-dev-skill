# 界面、操作与状态规格

仅检查当前模块实际涉及的部分，不为简单玩法引入网络、支付或组织权限系统。

## 界面覆盖

按实际界面和玩家操作顺序组织。界面复杂或跨多个弹窗时，在工作区维护简短覆盖记录：来源控件、触发条件、目标界面/状态、所属规格章节、版本范围及证据。少量控件可以直接在规格中说明，无须另建台账。

版本排除项按最小明确范围解释：排除一个按钮不等于删除其父界面。复用有证据的公共组件时，说明组件、数据绑定、变体及差异；只展开定制或未覆盖部分。不要虚构已有预制体或把公共数据引用等同于展示规格。

## 连续行为

对实际可操作对象写清初次进入、触发、处理中、成功、失败、取消/关闭和再次进入。只展开适用状态。

- 选择操作：哪些对象可选、重复点击、无效目标、成功后是否保留选中、切换对象的结果。
- 输入操作：提示、已保存值、草稿各是什么；完成/取消/关闭如何回填，回填是否等于外层提交；空值、长度、非法内容及失败后保留规则。公共输入组件只引用，不重写内部机制。
- 数量与确认：上下限及来源、边界按钮、联动结果、确认对象、取消与失败后的位置。
- 动画或自动结算：输入锁定时段、数据提交点、结束条件、重复操作是否产生重复结果。不能用动画先后替代业务判定顺序。
- 退出与恢复：恢复哪些逻辑状态，何时重新允许操作；未要求中间帧恢复时，不擅自增加逐帧续播。

## 展示与数据

区分实际业务状态、静态配置与计算显示。例如当前装水量来自盘面，容量来自规则/配置，剩余容量由两者相减。具体字段按项目证据命名，不为业务文档擅自增加协议或存档字段。

自制文本/列表区块按需说明字段、排列、条数、行数、换行、溢出、全文去向、空态、失败与刷新。展示容量、业务容量、输入字数是不同概念；不要因为需要说明布局就新增配置开关。触屏功能不能仅以鼠标悬停提供必要信息。

## 规则示例的使用

水滴排序可检查来源选择、无效目标、部分转移、锁定输入和自动结算交接；这些是检查方向，不是所有游戏的固定规则。具体容量、动画时长、完成条件和失败标准必须来自目标项目的有效规格。
